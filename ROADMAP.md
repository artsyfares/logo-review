# LogoAI Roadmap

Paced for a solo, AI-assisted build. Phase 0 and Phase 1 (the MVP) are broken into concrete tasks — check them off as they land. Phases 2+ are milestone-level outlines; each gets broken into a detailed task list when it becomes the active phase, informed by what was actually learned building the phases before it.

Every task should trace back to a section of [docs/PRODUCT_VISION.md](docs/PRODUCT_VISION.md). If you're about to do work that doesn't map to anything here or in the vision doc, stop and add it explicitly first rather than letting scope drift in silently.

**MVP definition (end of Phase 1):** a signed-in user can create a project, upload a logo, receive a full structured review (scores, confidence, strengths/weaknesses, redesign directions, all with reasoning), and have a follow-up conversation about it — with everything persisted for their next visit. No production toolkit, no brand guidelines doc, no collaboration features yet.

## Phase 1 — MVP: Core Review Loop

**Goal:** the full upload → structured review → conversation loop, end to end.

- [x] **1.1 Review schema** — defined in `packages/shared` as Zod schemas (`logoReviewSchema`, `scoredDimensionSchema`, `redesignDirectionSchema`). Verified via `zod-to-json-schema` that every score field structurally requires reasoning/confidence/principles — no bare-number score is representable anywhere in the tree. Wired into `apps/web`'s Drizzle `reviews.reviewData` column for type-safe jsonb storage.
- [x] **1.2 Deterministic analysis engine** (`services/analysis`) — real computation, all verified with passing tests + live smoke tests, not placeholders:
  - [x] 1.2a Raster ingestion & basic properties (Pillow): dimensions, format, transparency.
  - [x] 1.2b Vector ingestion & structure (lxml) for SVG uploads: path count, groups, embedded text/raster-image detection. Used lxml instead of svgelements (sufficient for structural counts; hardened against XXE with `resolve_entities=False`/`no_network=True`/`load_dtd=False`, verified with a real malicious-payload test).
  - [x] 1.2c Color palette extraction (median-cut quantization on alpha-filtered opaque pixels) + WCAG 2.x contrast (verified white-vs-black ratio == 21 exactly). **Follow-up fix:** artwork with a baked-in background fill (an SVG background rect, or a raster flattened onto a solid color) was having that fill quantized as if it were foreground ink, producing nonsense feedback like "the logo's white color fails contrast against a white background." Added `detect_background_color` (corner-sampling heuristic) to exclude the canvas fill from the palette/contrast checks and instead report `contrast_vs_own_background` — what the logo actually looks like today — alongside the existing hypothetical white/black placements. Covered by new tests in `test_color.py`.
  - [x] 1.2d Composition metrics: bilateral (vertical-axis) symmetry cropped to the artwork's own bounding box, whitespace/negative-space ratio.
  - [x] 1.2e Scalability signal: edge-density retention at 16/32/48px vs. full resolution, aspect-ratio-preserving (verified wide wordmark logos don't get squashed into a square).
  - [x] 1.2f `AnalysisFacts` Pydantic response model returned by `/analyze` for both raster and SVG uploads (SVG rasterized via `resvg_py`, chosen over `cairosvg` after confirming cairosvg's native Cairo dependency doesn't install cleanly on Windows dev machines).
- [x] **1.3 AI review generation** — `apps/web/src/lib/ai/` calls Claude (`claude-opus-4-8` — see CLAUDE.md rationale) with tool-use forced against the Phase 1.1 schema. Verified live end-to-end: real test logo → real `services/analysis` facts → real Claude call → schema-validated review whose reasoning correctly cited exact computed numbers (symmetry, contrast, whitespace) rather than re-estimating them. **Note for 1.4:** this function requires a raster image (PNG/JPEG/GIF/WebP) — SVG uploads must be rasterized before calling it; `services/analysis` already does this internally via `resvg_py` but doesn't yet expose the rendered PNG back to `apps/web`, so 1.4's orchestration needs to either request that back from the analysis service or rasterize independently.
- [x] **1.4 Review persistence** — `generateReview(logoAssetId)` server action: fetches the asset from R2, calls `services/analysis`, calls the AI provider, writes the review row (pending → complete/failed). Also extended `AnalysisFacts` with `rendered_png_base64` (verified live — valid PNG, correct dimensions) so `apps/web` never needs its own SVG rasterization. Project page has a bare "Generate review" trigger + minimal result display (real UI is 1.5's job). **Not yet live-tested end-to-end** — needs a real `DATABASE_URL` (Neon still not provisioned); typecheck/lint/build all pass and every non-DB piece (R2 fetch, analysis-service call, AI call) is independently verified.
- [x] **1.5 Structured review UI** — `apps/web/src/components/review/` renders every part of the review shape as dedicated sections (no single prose blob): overall-quality paragraph, strengths/weaknesses/improvement lists, category-by-category commentary, redesign directions, recommendations, readiness & accessibility. Caught and fixed a real bug in the process: the AI was scoring on an implicit 1-10 scale despite the schema requiring 0-100 (Zod's `min(0).max(100)` doesn't reject 6 or 7.5, so it passed validation silently) — fixed with an explicit `.describe()` on the score field plus a system-prompt instruction; existing DB rows predate the fix and will still show old-scale scores until re-reviewed. **Revised after user feedback (round 1):** the first pass used dashboard-style score bars, colored pills, and card grids — rejected as feeling corporate rather than like a designer's written critique (referenced https://mylogo.review for voice, not layout). Rebuilt as flowing prose paragraphs — scores stated inline in text, confidence/principles as a single italic line, no bars/badges/colors — and the AI system prompt now explicitly instructs a senior-designer critique voice instead of audit-report language.
  **Revised after user feedback (round 2):** "no visualization" was too literal — user wanted no *dashboard chrome*, not no visuals. Added `ScoreRing` (SVG donut per score), `ColorPaletteSwatches` (the actual extracted hex colors, not AI-described ones), and `LogoThumbnail` (the real reviewed logo image, with an alignment-grid overlay for the composition section) alongside the prose. Required a new `reviews.facts` jsonb column (migration `0001_petite_lockheed.sql`) to persist the `AnalysisFacts` the review was generated from, since the UI needs the real palette/rendered-image data, not just the AI's text.
- [x] **1.6 Conversational follow-up** — chat scoped to a single review (matches the existing `review_messages.review_id` FK from Phase 0.4), not project-wide across logo versions. `AIReviewProvider` gained a `generateChatReply` method (implemented for both Anthropic and Gemini) alongside the existing `generateLogoReview`; the chat system prompt (`apps/web/src/lib/ai/chat-system-prompt.ts`) keeps the same senior-designer voice, is grounded in the stored `LogoReview` + `AnalysisFacts` so it never re-derives or contradicts them, and is explicit that the AI can only propose changes in words, never claim to have generated/edited an actual file. `sendReviewMessage` server action persists both sides of each turn to `review_messages`. Reviews from before the `facts` column existed show "regenerate to enable chat" instead of a broken chat box.
- [x] **1.7 Project dashboard** — list/create projects and multi-version upload already existed from Phase 0.6; this closed the remaining gaps. `/projects` now shows each project's logo count and creation date, newest-first, instead of a bare name list. `/projects/[projectId]` gained a "← All projects" breadcrumb and now orders logo versions newest-first with each version's upload date shown — the existing version-per-asset schema (`logoAssets.version`, auto-incremented in `recordLogoAsset`) already gives every re-upload its own row with its own review, which is what "review history per project" actually means here: history is per logo version, not a separate log of repeated attempts at reviewing the same file.
- [x] **1.8 Golden-path + edge-case pass** — normal raster logo already verified live end-to-end in earlier phases (upload → B2 → analysis → AI review → chat). Exercised the remaining cases directly against `services/analysis`'s `/analyze` (no auth needed there, and it's the layer where format/structure bugs actually surface):
  - Symbol-only SVG (circle, no text): correct — `has_embedded_text: false`, background correctly `null` for a transparent canvas, near-perfect symmetry for a centered shape.
  - Text-only wordmark, both SVG (`<text>` element) and raster: confirmed `resvg_py` actually renders text via system font fallback rather than producing a blank image — a real, previously-unverified risk. `has_embedded_text: true` detected correctly.
  - **Found and fixed a real bug in the process**, the same class of bug as 1.2c's contrast fix: `whitespace_ratio`/`vertical_symmetry_score`/`bounding_box` only treated true alpha-transparency as "non-ink," so artwork with a baked-in opaque background (common for exported wordmarks) read as "0% whitespace" and — worse — always scored a false 1.0 on symmetry, because a fully-opaque canvas makes the ink mask uniform and trivially self-mirroring regardless of actual content. Fixed by threading the already-detected `background_color` into all three composition functions (`background_rgb` param, defaults to `None` so unaffected callers are unchanged); confirmed against a real rendered wordmark going from `whitespace_ratio: 0.0` (wrong) to `0.885` (correct, matching the real ~88% background coverage). 4 new tests in `test_composition.py`, one deliberately asserting the old buggy value too so a future regression is caught either direction.
  - Oversized file: verified via code read (not live, since it requires an authenticated browser session) — `apps/web`'s presign route rejects by client-reported size before any bytes move, and `recordLogoAsset` independently re-verifies the real size via `HeadObjectCommand` and deletes the object if it's still over the limit even if the presign check were bypassed. Both return a clear error message, no silent failure.
  - Unsupported format (`.bmp`/octet-stream): clean `400 Unsupported content type: ...`, not a crash — same for a corrupt file that claims to be a PNG (`400 Could not decode image`), confirming `main.py`'s try/except boundaries actually catch bad input rather than leaking a raw traceback.
  - Large raster (3000×3000): processed in ~3s with correct facts, no timeout or memory blowup from the median-cut quantization step.
  - Not independently re-tested: a real SVG through the full AI-review call (only PNG has been exercised end-to-end through Gemini/Claude so far) — low risk since the AI layer treats `facts` as opaque JSON regardless of `kind`, but worth one real upload to close the loop with zero remaining doubt.

All 40 `services/analysis` tests pass (36 → 40 after the composition fix's new tests).

**Definition of done:** matches the MVP definition at the top of this document, deployed and usable by you end to end. All 1.1-1.8 tasks are complete — the one remaining gap against "deployed" is Phase 0.8 (Vercel/Fly), deferred at your request.
